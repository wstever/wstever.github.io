# 为什么把知识装进 Skill

## 提示词的天花板

大多数人用 AI 的方式，是每次对话都把背景讲一遍：我是谁，我要什么，我以前怎么做的。讲第三次的时候，你会开始怀疑人生——我到底是在用 AI，还是在给 AI 当客服。

问题出在提示词是**一次性**的。它活在单次对话里，对话结束就蒸发了。你积累的所有经验——怎么批卷子、怎么写客诉日报、怎么拆解一个需求——都锁在你的脑子里，AI 一点都拿不走。

## Skill 是什么

Skill 可以理解成**把"怎么做一件事"写成 AI 能调用的流程**。

普通的知识是"我有这份教案"。Skill 是"让 AI 按我的套路，二十分钟出一份同类教案"。前者是仓库里的一摞纸，后者是一个加班的员工。

一个 Skill 通常包含三样东西：触发条件（什么时候用它）、执行步骤（按什么顺序干什么）、产出标准（做成什么样算合格）。写清楚这三样，AI 就能在你不在场的时候，按你的套路干活。

## 什么经验值得 Skill 化

判断标准很简单：**你每周要重复做三遍以上的事，就值得**。

批周测卷、归客诉、整理会议纪要、导出逐字稿归档——这些都是。反过来，一次性的创意劳动、偶尔为之的调研，暂时不值得，等流程稳定了再说。

还有个隐藏信号：如果你教过别人做某件事，那件事就该 Skill 化。能教人的流程，AI 就能跑。

## 我的实践路径

我的 Skill 化是从最小场景开始的：

- **douyin-copy-extract**：看到好文案，一键提取口播结构并归档
- **会议逐字稿转纪要**：两万字原文进来，结构化纪要出去，原文进知识库
- **学情分析批阅**：卷子截图进来，批阅表格和反馈草稿出去

每一个都不大，但每一个都真实地每周在跑。Skill 的价值不在数量，在调用频率——没人用的 Skill 和没写是一样的。
