说说企业级 Agent：在工厂里搓了半年，聊点实在的

2026年10月13日 · 阅读需 10 分钟
本本本添哥
供应链数字化 / AI 落地实践者

开个帖子聊聊企业级 AI Agent 这个话题。

网上关于 Agent 的文章多如牛毛。有人讲架构，有人讲 Prompt 工程，有人讲 MCP 和工具调用，读起来都很兴奋，好像明天企业就要被 Agent 颠覆了。但我自己是真在工厂里搓 Agent 的——2026 年 6 月入职联想 GSC，all in AI 应用开发和 Agent 平台建设，半年下来感触挺多。今天抛开那些宏大概念，纯粹从一个一线落地者的角度，聊聊企业级 Agent 的本质、里面的坑，以及作为个人该用什么心态参与。

1. 企业级 Agent 到底是个啥逻辑？​

很多人一听到"企业级 Agent"，脑子里浮现的就是 ChatGPT 套个壳，再接几个内部 API，然后"嗖"一下业务就自动化了。

但真蹲到工厂里你会发现，事情完全不是这个路径。

先说我们面对的家底。联想 LME 这条线，光核心系统就有十九个——ECC、APS、MES、WMS、QMS 这些，加上十条端到端的核心业务流程。一个采购流程，可能要从 SRM 走到 ERP，再走到 MES，最后落到 WMS 发货。每个系统都有自己的接口规范、权限模型和数据口径。Agent 要在这条链路上跑通，不是"聪明"就行，是得听得懂每个系统的方言。

我们做的 Agent 平台叫 iChain，底下的数据底座叫 LUDP。名字听着很 fancy，但干的事情说穿了就一句：把业务里那些重复的、跨系统的、靠人肉跑腿的流程，织成一条 Agent 能跑的链。

这里有个认知差特别大：在外面演示的 Demo，和在生产环境跑着的 Agent，根本不是一个物种。Demo 里三步搞定，生产环境里可能有三十个异常分支要处理——某个接口超时了怎么办？某个字段突然为空了怎么办？业务方昨天刚改了审批规则怎么办？这些事，PPT 里不会写。

2. 落地路上三个绕不过去的坑​

2.1 业务方要的不是 Agent，是"昨天的客诉归好类"​

这是最扎心的一点。

业务方来找你，开口永远是："我们想上 AI"。你追问想解决什么问题，对方说"就是想提效嘛"。这种对话我经历了不下二十次。

但"提效"不是需求，是情绪。真正的需求得往下挖三层：是哪个岗位、在哪个时间点、因为哪个具体动作、重复了多久、造成了什么后果。挖到最后，往往落在一句特别朴素的话上——"运营早上九点想看到昨天的客诉归好类排好序"。

Agent 技术圈爱谈模型多强、框架多优雅。但企业级落地里，最值钱的能力根本不是技术，是把"我们想提效"这种废话，翻译成"周一早上八点，运营打开电脑就能看到昨天的异常订单归因"这种能验收的东西。翻译不出来，Agent 再强也是个玩具。

2.2 数据底座不干净，Agent 就是空中楼阁​

第二个坑，是数据。

我见过太多项目，上来就选模型、搭框架、画架构图，跑了两周发现接进来的数据全是脏的。同一个物料编码，ERP 里叫 A，MES 里叫 B，WMS 里叫 C。Agent 拿着这种数据去做决策，比不用 Agent 还可怕——它一本正经地胡说八道，业务方还信了。

所以我们现在的顺序是反的：先看数据底座干不干净，再谈 Agent。LUDP 这个数据平台存在的意义，就是把十九个系统的数据口径先对齐，Agent 才能在上面跑。数据不通的地方，Agent 接得越多，事故越大。

这也解释了为什么制造业的 AI 落地比互联网慢一拍。互联网公司的数据天生在自己的闭环里，制造业的数据散在十九个异构系统里，光清洗和对齐就是一两年的工程。急不来。

2.3 稳定性比智能重要一百倍​

第三个坑，是稳定性。

消费级 AI 产品，答错了用户笑一笑就过去了。企业级 Agent 要是在发货流程里答错一步，那是真金白银的损失。

所以我们内部有个不成文的规矩：能规则解决的，别交给模型。 模型只处理那些真正模糊的、需要语义理解的环节——比如把客户的抱怨归类成"物流慢"还是"质量差"。剩下的流程路由、字段校验、状态流转，老老实实写规则。很多人觉得这不够"AI"，但生产环境里，一个不会出错的规则，胜过十个偶尔惊艳但偶尔抽风的模型。

3. 聊聊落地过程中的各方​

在企业级 Agent 这个圈子里，不同角色的处境完全不一样。

3.1 业务方：怕被替代，又怕被落下​

这是最微妙的一方。

一线业务同学对 Agent 的态度特别拧巴。一方面，他们是重复劳动的直接受害者，心里清楚这些活儿不该人干；另一方面，又隐隐担心"AI 把我活干了，我怎么办"。

我的经验是，别跟他们讲"Agent 是来帮你的"这种空话。空话听多了反而警惕。不如直接坐下来，看他一天怎么干活，把他最烦的那件事拎出来——比如每周五要花半天手工导出三张表合并——然后说：这个事我帮你自动化，你省下的时间去干更有判断含量的活。

业务方不害怕 AI，他们害怕的是失控。 你让他看到 Agent 只是把他从表堆里捞出来，而不是把他捞走，他自然会帮你。

3.2 IT：要的是稳定，不是炫酷​

IT 部门是另一个故事。

任何一个新 Agent 要接进生产环境，IT 第一反应不是"哇好酷"，是"权限怎么走？日志怎么留？出问题怎么回滚？"。这不是保守，这是职责——十九个系统跑着整个公司的供应链，不能因为一个 Agent 原型就搞停一条线。

所以企业级 Agent 的开发节奏，和互联网产品完全是两个物种。互联网是快速迭代，企业级是慢就是快。你花两周把一个 Agent 打磨到 95 分再接进去，比花两周做个 60 分的原型被 IT 拒掉，要快得多。

3.3 开发者：Demo 五分钟，接系统两个月​

这可能是最有共鸣的一方。

在笔记本上跑 Demo，调两个 API，写一段 Prompt，五分钟出效果。真要接进生产，光是摸清每个系统的接口文档、申请权限、处理异常分支、写监控和告警，两个月都算快的。

我自己之前做电商客服数据分析、做教师工作流 Agent，都是单链路、小范围，几天就能跑通。换到企业级场景，光是一个跨系统的审批流，就得把五个系统的状态机对齐。这种活儿不性感，但这才是企业级 Agent 的真实工作量。

4. 个人该持什么心态？​

说了这么多现实问题，那我们普通开发者，到底该以什么姿势参与这波浪潮？

我总结三条自己踩坑后得出来的体会。

4.1 别当技术传教士​

这是最重要的一条。

很多同学进了企业，学了几个月大模型，就开始到处布道："你们这个流程也该上 AI""你们那个报表也该 Agent 化"。业务方表面点头，心里想的是"你先把我这个月报做出来再说"。

技术是解决方案，不是信仰。 别拿着锤子找钉子。先坐到业务对面，听他们抱怨，听他们吐槽，听他们说"这事儿每周要耗我半天"。听到那个具体的痛点，再决定上不上 Agent。上对了，你是救星；上错了，你是麻烦制造者。

4.2 关注那些"能带走的东西"​

在企业里做 Agent 落地，有些东西是这家公司特有的——比如内部系统的接口规范、特定流程的审批逻辑、公司内部的组织文化。这些你离开这家公司就带不走。

什么是能带走的？

  • 需求翻译能力：把业务方模糊的抱怨，翻译成可验收的技术需求。这个能力在任何行业都值钱。
  • 流程抽象能力：从一条具体的业务流程里，抽象出通用的模式。下次换个行业，你知道该从哪里下手。
  • 跨部门协作能力：在业务、IT、数据、安全之间斡旋，把一个项目推上线。这种能力比任何框架都稀缺。
  • 对"脏数据"的敏感度：知道一个 Agent 在生产环境会被哪些真实世界的意外搞崩。这是 Demo 玩家永远学不到的。

4.3 进退从容，别 all in 在某个具体项目上​

技术风向变得太快。三年前大家还在聊微服务和云原生，现在全行业都在往大模型和 Agent 上扑。公司的战略会调，项目的优先级会变，今天的明星项目可能明天就资源缩减。

我的态度是：在这个项目里的时候，就把它扎扎实实干好，把上面那些能带走的能力学到手；如果哪天风向变了、项目调整了，也别内耗。项目有生命周期，但你练出来的需求翻译能力、流程抽象能力、跨部门推动能力，永远是你的。

顺便说一句，今年 9 月我还入选了清华大学教育学院 MAIC 项目的首批学习体验官，在企业落地之外，也在从教育的视角回看 AI 到底该怎么学、怎么教。两边视角对照着看，很多事情会更清楚。

说到底，企业级 Agent 这件事，技术从来不是最难的部分。难的是耐心——耐心听业务方把话说完，耐心把数据洗干净，耐心把异常分支补全，耐心接受"慢就是快"。

网上那些三个月颠覆某个行业的故事，听听就好。真在工厂里搓过 Agent 的人都知道，改变一个流程，比训练一个模型难一百倍。

但也正因为难，做成了才有价值。
